# DECISIONS

Формат: что решено → почему → как откатить.

## D1. name_filter.py восстановлен из чата
- **Что:** файла в корне не было. Создал `name_filter.py` дословно из кода, вставленного в чат
  (вернул переносы строк, логику не менял).
- **Почему:** без него нет фаз 4, 5, 9; ждать нельзя по условиям задания.
- **Проверка:** theblackstripe.com OK 60, tjhbw.com NO (абракадабра), bestcheapdeals.com NO 20 (MFA),
  hl-design.de OK 30 — совпадает с ожиданиями.
- **Откат:** положить свой `name_filter.py` поверх.

## D2. Стартовые wordlists/
- **Что:** `spam.txt` и `brands.txt` — из NAME_BLOCKLIST; `mfa.txt` — 17 слов купонных/обзорных
  сайтов (best, cheap, deals, review, top …); `gambling.txt` — 10 слов (только флаг).
- **Почему:** содержимого оригинальных словарей в чате не было; без mfa.txt bestcheapdeals.com проходит.
- **Откат:** заменить файлы своими → `python run_daily.py --no-scrape --rescore`.

## D3. TR_MAX = 2 оставлен
- **Что:** в новом составе filters.py его нет, но это действующий фильтр сайта (Trust Ratio ≤ 2), с ним собрана выборка.
- **Почему:** убрать — значит молча изменить выдачу сайта.
- **Откат:** удалить строку `TR_MAX` в filters.py и `("fmseotrmax", ...)` в search_form.STATIC_FIELDS.

## D4. rank.py удалён
- **Что:** прототип ранжирования (MCP-полосы, штрафы) заменён `score.py` по новой формуле; его константы убраны из filters.py.
- **Откат:** восстановить из истории/чата не нужно — формула целиком описана в задании и в score.py.

## D5. Где лежат HTML и CSV
- **Что:** живой сбор пишет в `domains_ГГГГ-ММ-ДД/run_<id>/` (page_*.html, domains.csv, report.txt, verify_report.txt).
  Подпапка на прогон — чтобы второй прогон за день не смешивался с первым. Папки старше `HTML_KEEP_DAYS` (7) удаляются.
  Это заменяет схему «одна папка domains/, перезапись в конце» из прошлого задания.
- `--from-html <папка>` пишет CSV/отчёт в `<папка>/parsed_run_<id>/`, HTML не копирует.
- HTML тестовой выборки перенесён: `domains/` → `sample/pages_2026-10-02/` (рядом с sample CSV, вне зоны автоудаления).
- Старая папка `domains_2026-10-02/` (первый пробный прогон 2 стр. без фильтров) удалится автоматически через 7 дней.

## D5a. Продолжение оборванного прогона
- **Что:** прогон того же режима и того же поиска (URL) за этот же день со статусом `running` продолжается
  со следующей страницы (`start=` в URL). Дубли внутри прогона отсекаются по базе.
- **Откат:** удалить ветку `db.unfinished_run` в `scraper.collect`.

## D5b. Обычный режим
- **Что:** обычный режим = те же страницы, что и full, но не больше `MAX_PAGES` (10). В базу пишется всё,
  а «только изменения» обеспечивает upsert: неизменённые домены не сбрасывают статус и балл.

## D6. Темы Majestic для topic и отсечки
- **Что:** criteria.yaml → префиксы первой темы TTF:
  - preferred (politics, society, history, travel, sports, games) → `Society` (Politics, History, Government… внутри),
    `Sports`, `Recreation/Travel`, `Games`;
  - not_preferred (health, pets) → `Health`, `Recreation/Pets`;
  - hard_no → `FORBIDDEN_TOPICS = ["Adult", "Kids and Teens"]` — отсечка «запрещённая тематика».
    «Личные сайты (имяфамилия.tld)» по теме не определить — не реализовано (Q2).
- **Почему:** Majestic не имеет отдельной категории Politics/History — они внутри Society. News/Arts оставлены нейтральными.
- **Откат:** поправить списки в filters.py → `--no-scrape --rescore`.

## D7. Пустые значения
- **Что:** пустая метрика → часть = 0 и флаг «нет данных: X». Отсечка MCP < 12 срабатывает только если MCP известен.
  Множитель не применяется, если для него нет данных (MDP = 0, нет MRDL/BL, TF = 0).
- **Откат:** `score.cutoff` / `score.compute`.

## D8. «Дроп сегодня» в выгрузке
- **Что (исправлено 2026-10-03):** в выгрузку — только End Date позже дня выгрузки (сегодня). Раньше сравнивалось с last_seen, и вчерашние домены с дропом сегодня попадали в топ. Домены с ранним End Date получают балл и статус scored, но в top_*.csv не попадают;
  в отчёте отдельная строка «scored, но дроп в день сбора». Статус `dropped` — только когда End Date < сегодня.
- **Почему:** так «сегодняшние» видны в базе и отчёте, но не тратят место в выгрузке.

## D9. run_daily: дополнительные флаги
- `--import-csv` (загрузка sample без сайта), `--rescore` (пересчёт после правки порогов/словарей),
  `--db` (другая база — для тестов). `--rescore` сбрасывает в new всё, кроме dropped; имя и балл считаются заново.

## D10. Порядок проверки имени
- Имя проверяется по `domain_display` (с регистром) — так работает разбивка CamelCase (FreeCadWeb → free+cad+web).

## D11. TOP_N = 20, проблемы сбора — в results/problems/ (2026-10-03)
- **Что:** уточнено пользователем: сбор 20 страниц (`MAX_PAGES = 20`, обычный режим), выгрузка `TOP_N = 400`.
- При любой проблеме сбора (нет таблицы → нужен код/проверка, вход не удался, сбор упал) `scraper.save_problem`
  сохраняет `results/problems/ГГГГ-ММ-ДД_ЧЧММСС_мс.png/.html/.txt` (скриншот, страница, причина, URL, начало текста).
  run_daily в итоге показывает число проблем за день.
- **Откат:** `TOP_N` в filters.py; если имелось в виду 20 страниц — `MAX_PAGES = 20` и запуск без `--full`.

## D12. Лимит сайта ~51 страница на поиск (2026-10-09)
- **Что:** на странице 52 (start=10200) сайт пишет «You have reached the maximum page limit. You can use the filter
  and sort functionality to find more matches». Один поиск = не больше ~10 200 строк (51 × 200).
- `scraper.scrape_search` распознаёт это сообщение: прогон считается законченным («лимит сайта» в отчёте),
  пользователя не ждёт.
- **Следствие:** при сортировке по домену доступна только первая треть алфавита окна (~190 страниц). Чтобы собрать
  всё окно, нужно делить поиск (обратная сортировка или диапазоны TF/зоны) — см. Q5.
